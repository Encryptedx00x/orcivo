# 03.1-P00 — Recuperação do Repositório

## Objetivo

Encerrar a recuperação definida em `docs/GIT_RECOVERY_PLAN.md`, deixando o Orcivo como repositório independente, com histórico preservado, documentação/handoff versionados, remote privado controlado e working tree reproduzível.

## Arquivos e áreas prováveis

- Metadados Git do pai e do candidato, sem editar o código.
- `.gitignore` do candidato; eventualmente regra/exclude do Git pai.
- Documentação/handoff/planejamento atualmente não rastreados.
- Manifestos privados no diretório de recovery, nunca no repositório.
- `03.1-P00-SUMMARY.md` ao final da execução.

## Dependências

- Aprovação humana explícita para iniciar a recuperação.
- Destino de backup privado aprovado.
- Janela sem processos escrevendo no workspace.
- URL/owner do remote privado apenas no gate correspondente.
- Plan-check somente leitura para o identificador `03.1`.

## Riscos principais

R-GIT-01 a R-GIT-04. O risco dominante é operar no Git pai, perder arquivos não rastreados ou continuar após falha do helper/comando nativo. O plano de recuperação é a especificação vinculante; este plano não a substitui.

## Testes automáticos

- Igualdade entre source subtree tree hash e candidate `HEAD^{tree}` antes do transporte.
- Igualdade da lista inicial de 432 arquivos.
- Igualdade do manifesto de paths não rastreados antes do transporte.
- Contagem/log dos 161 commits do path comparada ao histórico extraído; diferença explicada bloqueia cutover.
- `git fsck --full` no candidato.
- `git diff --cached --check`, scan de nomes sensíveis e arquivos proibidos.
- Instalação frozen e baseline dos comandos do monorepo.
- `git status --short --branch` e SHA local/remoto após push aprovado.

## Testes humanos

- Confirmar que o remote é privado no provedor.
- Conferir visualmente marcos históricos e arquivo/handoff esperado.
- Confirmar que nenhum `.env`, token, certificado, prompt ou build foi versionado.
- Ensaiar o rollback por leitura dos paths/comandos, sem apagar o archive.

## Critérios de aceite

- Git toplevel do path Orcivo é o próprio diretório.
- Git pai e bundle permanecem íntegros.
- Histórico/árvore passam nos gates ou qualquer diferença está formalmente aprovada.
- Remote privado e primeiro push estão confirmados.
- Working tree contém somente arquivos locais ignorados esperados.
- Archive original não foi removido.
- P00 summary registra todos os HUMAN_APPROVAL com data/responsável.

## Rollback

Antes do cutover, abandonar o candidato e manter origem/backup. Depois do cutover, renomear o candidato para `recovery-failed` e restaurar o archive; nada é apagado. Se o detach do índice pai já foi commitado, usar `git revert` com aprovação, nunca reset/rewrite.

## Commit sugerido

Os commits da recuperação e do detach estão registrados no summary. O closeout documental usa `docs(03.1): close repository recovery wave`.

## Não fazer

- Não rodar subtree no Git pai.
- Não usar force push, reset, clean, filter-branch ou exclusão.
- Não copiar tudo por wildcard.
- Não configurar remote público ou token em URL.
- Não remover o archive ou o Git pai.
- Não considerar nenhuma outra wave encerrada antes deste gate.
