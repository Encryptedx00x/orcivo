# 03.1-P10 — Fidelidade Visual

## Objetivo

Corrigir composição, hierarquia, responsividade e estados das superfícies existentes usando o handoff aprovado como referência real; produzir baseline automatizada pronta para revisão humana, não apenas prova por tokens ou grep. A revisão em dispositivo e o sign-off ocorrem no UAT posterior.

## Referências obrigatórias

- `docs/design-handoff/orcivo-design-system/`.
- `docs/FRONTEND_DESIGN_MASTER.md` com precedência registrada no Context.
- `docs/OPERATIONS_UI_MISSING_SPECS.md`.
- `docs/screens/`, `docs/ui_kits/`, PDFs e HTMLs de referência.
- Matriz funcional real de P07; stubs/futuro não podem parecer implementados.

## Arquivos prováveis

- Layout/shell/components/styles web e páginas existentes.
- Navigation/screens/styles mobile existentes.
- Public approval e PDF renderer.
- `loading.tsx`, `error.tsx`, `not-found.tsx` e empty states.
- Testes/snapshots/screenshot specs e relatório de comparação.

## Dependências

- P07: contratos reais e dados fake removidos.
- P08: gates verdes.
- P09: ambiente/fixtures para render real.
- Nenhuma mudança do design system sem aprovação humana.

## Riscos

R-VIS-01 e R-VIS-02. Aplicar tokens sem reproduzir estrutura cria falsa fidelidade; documentos antigos contêm azul legado/conflitos.

## Testes automáticos

- Screenshot tests nos viewports definidos, dados curto/longo/vazio/erro/loading.
- Assertions de ausência de overflow/overlap e elementos fora da viewport.
- Navegação por teclado/foco e labels básicos nos forms alterados.
- Busca de cor azul legada fora de allowlist explícita.
- Busca de identidade/dados fake e termos comerciais proibidos.
- PDF A4 com 1/30 itens, acentos, valores, assinatura e quebra de página.
- Canvas/approval responsivo com eventos touch simulados, seguido de UAT físico.

## Testes humanos

Estes testes são preparados em P10 e executados apenas no Gate UAT. Eles não são critério para declarar P10 concluído:

- Comparar lado a lado com HTML/JSX/PDF de referência, não só tokens.
- Executar 1440, 1024, 768, 390 e 360 px.
- Android físico para auth, clientes, catálogo, orçamento, OS/fotos e aprovação touch.
- API lenta/desligada/vazia para loading/error/empty.
- Registrar PASS/FAIL por tela, referência e gap.

## Critérios de aceite

- Nenhuma tela principal fica em “MVP genérico” quando há referência executável para o escopo existente.
- Layouts respondem sem overlap/overflow nos viewports definidos.
- Estados loading/error/404/empty são distinguíveis e honestos.
- Shell não contém identidade fake.
- Mobile/PDF/aprovação têm baseline automatizada e manifesto `ready_for_UAT`; a evidência física permanece pendente para STAB-H/I.
- Tokens corretos sozinhos não são usados como prova.
- Gate R repete P08 depois da última alteração e fica verde antes de qualquer caso humano.

## Rollback

Reverter por tela/componente em commits pequenos. Não restaurar dados fake, handler morto ou azul legado como rollback. Se referência conflitar, pausar a tela e abrir decisão, sem recriar design.

## Commit sugerido

## Não fazer

- Não recriar design system.
- Não avaliar apenas cor/token.
- Não adicionar feature para preencher tela ausente.
- Não aprovar UI sem screenshots/viewport/dispositivo.
- Não mascarar erro de API como estado vazio.
