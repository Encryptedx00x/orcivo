## Blocker — harness de integração quebrado (pré-existente)

Os 4 specs `src/**/*.isolation.spec.ts` (única cobertura real de integração;
`*.e2e.spec.ts` são `it.todo`, `billing.e2e-spec.ts` não casa o `testRegex`)
falham no `beforeAll` **no baseline, antes das mudanças de P02**:

- `POST /auth/signup/user` exige `accepted_terms: z.literal(true)`
  (`SignupStep1Schema`), mas os specs enviam `{ name, email, phone, password }`
  sem esse campo → 400 → `access_token` fica `undefined` → todo o fluxo vira
  `Bearer undefined` → `401` em todas as asserções.
- `customer_type: 'INDIVIDUAL'` nos specs não existe no DTO (`type: 'PF'|'PJ'`);
  hoje é descartado pelo `whitelist` — não é o bloqueador, mas precisa corrigir.

Verificado: `git stash` + rodar `customer.isolation.spec.ts` → mesmas 2 falhas
`expected 200, got 401`. As mudanças de P02 são **net-neutras** nesses specs.

**Para destravar T08/T09** (próxima sessão):
1. Corrigir `beforeAll` dos 4 specs (`accepted_terms: true`, remover `customer_type`).
   Recomendado extrair um helper `test/tenant-factory.ts`.
2. `docker compose -f infra/docker-compose.test.yml up -d` + migrate; adicionar
   MinIO ao compose de teste (hoje ausente — `StorageService.onModuleInit`
   conecta no boot e derruba `app.init()` sem ele).
3. Escrever a suíte P02: invite cross-tenant (G-1), RBAC role-negativo (G-4),
   ownership cross-tenant de IDs relacionados (T06).
4. Isto encosta em escopo de P08 (baseline de qualidade / CI). CI ainda usa
   `prisma db push --force-reset` — trocar por `migrate deploy` fica em P08.
