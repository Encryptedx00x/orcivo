# 03.1-P08 — Baseline de Qualidade

## Objetivo

Estabelecer uma matriz reproduzível e verde de typecheck, lint, build, Prisma, unit, integration, tenant e Docker em todos os workspaces, usando banco isolado e sem correção automática indiscriminada.

## Arquivos prováveis

- Package scripts raiz e dos apps/packages; Turbo config.
- ESLint/TypeScript/Next/Jest configs por workspace.
- Test setup/globalSetup/cleanup e fixtures de integração.
- Código estritamente necessário para fechar erros de typecheck/lint/build.
- CI workflows, somente depois da execução local estável.
- Runbook/matriz de comandos.

## Dependências

- P01–P07 integrados.
- Standalone limpo e lockfile confiável.
- PostgreSQL/Redis/MinIO efêmeros ou namespaced.

## Riscos

R-QA-01, R-QA-02 e R-QA-03. O maior risco é um teste apagar banco de desenvolvimento ou um script de lint modificar arquivos além do escopo.

## Testes automáticos

Matriz mínima futura:

```powershell
corepack pnpm install --frozen-lockfile
corepack pnpm typecheck
corepack pnpm lint
corepack pnpm test
corepack pnpm build
npx prisma validate
docker compose -f infra/docker-compose.dev.yml config --quiet
```

Complementos obrigatórios: migration-from-zero; integration isolada; tenant/RBAC; storage; aprovação/replay; auth/session; webhook/limits; PDF real; Docker backend start/health. Rodar uma segunda vez para detectar dependência de ordem/estado.

`apps/admin`, `packages/ui` ou qualquer outro workspace vazio/placeholder não pode aparecer como PASS por executar apenas `echo`, não possuir fontes ou omitir scripts. P08 registra `ACTIVE` com gates reais ou `SCAFFOLD/DEFERRED` com justificativa e owner.

## Testes humanos

- Revisar tabela comando/exit/warnings e exceções.
- Confirmar que o banco usado tem identificação descartável e não contém dados reais.
- Confirmar que `lint` check não edita arquivos.

## Critérios de aceite

- Typecheck/lint/build verdes em shared-types, backend, web, mobile e site; outros workspaces são `ACTIVE` com gates reais ou `SCAFFOLD/DEFERRED`, nunca PASS por placeholder.
- Prisma/schema/migrations/Docker verdes.
- Unit/integration/tenant/security passam em ambiente isolado duas vezes.
- Nenhum script toca banco dev/produção.
- Toda exceção está aprovada com prazo; idealmente zero.
- CI e local usam comandos equivalentes.

## Rollback

Reverter configs/correções pelo commit afetado. Nunca restaurar cleanup inseguro ou lint com fix automático como gate. Se CI divergir, manter mudança local e reverter somente workflow até investigar; não suprimir testes.

## Commit sugerido

`chore(quality): restore monorepo verification gates`

## Não fazer

- Não usar lint `--fix` em massa como validação.
- Não rodar E2E sem guard de DB antes do primeiro delete.
- Não marcar timeout/skipped como verde.
- Não remover teste para passar CI sem aprovação.
- Não misturar upgrades/refactors não necessários.
